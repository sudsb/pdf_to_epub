# 文字表格 → 程序原生表格 转换（设计文档）

日期：2026-10-17
状态：待实现

## 意图与原因

OCR 提示词要求模型「按原文原格式输出」，视觉模型遇到表格时最常见的产物是
**Markdown 管道表**（`| 社数 | 户数 |` + `|---|---|` 分隔行 + 数据行），且带 OCR
真实瑕疵：列数对不齐（表头 7 列、数据行常只有 6 格）、全角句号 `30。00`、角标
`〔1〕` 混进单元格、表题与表头挤在同一行。

当前程序对这类文本**不做任何处理**：它在编辑器里/导出物里就是一串带 `|` 的
普通文字，用户只能手搓成表格。而程序其实已有一整套原生表格能力（HTML
`<table>`：`thead/th` 表头、`colspan/rowspan`、水平/垂直对齐、列宽行高，可被
表格工具条编辑，并能一路导出为 EPUB/DOCX/MD/TXT）。

本功能补上**「文字 → 原生表格」的那座桥**：自动 + 手动双入口，尽量兼容模型
可能吐出的多种表格文字形态。

## 目标

1. **自动**：OCR 完成后，把每页识别文本里「像表格」的块自动转成原生 `<table>`，
   接入两条既有链路（默认结构化管线、矫正编辑器载入）。
2. **手动**：在矫正编辑器里选中一段文字，点弹出菜单的「转成表格」，就地完成转换
   （此路径额外支持**无竖线的空格/制表符对齐列**）。
3. **强兼容**：接受多种输入形态（见「兼容性规格」），并容忍常见 OCR 噪声。
4. **可开关**：设置界面里可切换，**默认开启**。

## 非目标

- **不跨页**：OCR 逐页进行，跨页表格合并是独立难题；每页独立识别（先记为超出范围）。
- **不覆盖「重新识别」路径**：`/api/reocr` 用字符级 diff 应用结果，纳入需要改造该机制；
  v1 只覆盖「OCR 完成后默认管线」与「矫正编辑器载入」两条路径。
- **真实 OCR 的空格对齐表不自动转**：仅手动模式对编辑器内手打的多空格文本生效
  （原因见「范围决定」）。
- **不做合并推断**：不尝试从文字里猜 `colspan/rowspan`；输出恒为规整网格，需要合并
  时用户用现成表格工具条手动合并。
- **不改导出语义**：`<table>` 在 `htmlmanage`/`correctmanage` 里已是「原子块」，
  本功能只负责产出这种块，不碰导出逻辑。
- **不引入 asyncio**，不新增第三方依赖。

## 反目标（即使技术可行也算失败）

- **误判**：普通正文里偶然出现的 `|` 被当成表格（自动模式必须要求分隔行，见下）。
- **破坏幂等**：`convert(convert(x)) != convert(x)`；已生成的 `<table>` 被再次改写。
- **弄脏既有链路**：默认 `mian.py epub` 管线、`test_*` 既有断言出现回归。
- **改坏存盘/历史**：矫正编辑器里已存 HTML（含用户手设标题、标记 span）被再次转换。
- **卡顿**：转换是纯字符串处理，必须 O(行数)；不得为转换引入额外网络/大模型调用。

## 约束

- Python ≥3.11、Windows、stdlib-only（unittest）；无新第三方依赖。
- 配置写盘走 `configmanage` 的 `_CFG_LOCK` + 原子写；不新增顶层危险状态。
- 锁序不变：config → session → engine/image；本功能是纯函数，不触碰 session/engine。
- 冻结 exe：新模块经 `mian.py` 分析自动收录（`ptoe.spec` 从 `mian.py` 起分析），
  无需改 spec；但新模块必须**可被正常 import**（不做动态/字符串导入）。
- 重依赖（`zhconv` 等）保持惰性；本功能只用 `re`/`html` 标准库。
- 前端无 JS 单测；以 `node --check ui/app.js` + Python 侧静态断言为准。

## 兼容性规格（输入形态 → 输出）

统一产出：`<table>` 单行 HTML（**不换行**，便于段落切分/原子透传），结构为
`<table><thead><tr><th>…</th>…</tr></thead><tbody><tr><td>…</td>…</tr>…</tbody></table>`。
单元格文本做 HTML 转义；不产出 `colspan/rowspan`。

**A. Markdown 管道表（自动 + 手动）**
- 识别锚点：连续 ≥2 行、每行含 ≥1 个**未转义**竖线（半角 `|`，兼容全角 `｜`/`︱`），
  且其中一行为**分隔行**：每格匹配 `:?-+:?`（允许空格），如 `|---|---|`、
  `:---|:--:|--:|`；兼容用全角破折号 `—`/`－` 当横线的兜底形态。
- **分隔行是「自动」模式的必需锚点**；**「手动」模式放宽**：用户既然已显式选中文字，
  就不再要求分隔行——有分隔行则用它定列数与对齐，没有则把首行当表头（见「已决定的做法」）。
- 分隔行的上一行 = 表头行；其下连续管道行 = 数据行；遇到非管道行停止。
- **单元格切分**：先把全角 `｜`/`︱` 归一为 `|`，再按未转义 `|` 切分；**只去掉行首
  的一个空单元（整行以 `|` 开头时）与行尾的一个空单元（整行以 `|` 结尾时）**，中间的
  空单元是真实空列（如你那张图里「省市名」列的表头本就是空的），必须保留。
- **列数基准 W**：有分隔行时 `W = 分隔行的单元格数`（md 语义）；手动模式无分隔行时
  `W = 各行最大单元格数`。
- **表题提取**：设分隔行单元数为 `W`。表头行若以 `|` 开头 → 无表题，整行都是单元；
  否则把整行按上述规则切分后，若**单元数恰为 `W + 1`**，则第一个单元是**表题**，
  提为表格上方的独立 `<p>`（显式 `<p>`，见「已决定的做法」），其余为表头单元；
  若单元数不等于 `W + 1`，则无表题、整行都是单元（兼容 `社数 | 户数` 这种无前导
  `|` 的表头）。用户例子 `1951年…情况 | | 社数 | …` 切出 8 个单元 = 7 + 1 → 表题成立。
- **列数不齐**：所有行（含表头）按 `W` 归一——不足补空单元格；超出则把多出的单元文本
  按顺序拼接进最后一格（保守，避免丢字）。
- 单元格：去首尾空白；`\|` → `|`；其余原样。
- 对齐：分隔格 `:---`→left、`---:`→right、`:---:`→center、`---`→无；落为单元格
  对齐 class（复用程序既有类名 `ptoe-align-left/center/right`）。

**B. ASCII 画框表（自动 + 手动）**
- 边框用 `┌─┬─┐ / ├─┼─┤ / └─┴─┘`，或 `+--+--+` 风格；按竖边框切列。
- 边框行是强信号，允许自动识别。

**C. 无竖线的空格/制表符对齐列（仅手动）**
- 用 ≥2 连续空格或 `\t` 作列分隔；由多行的空白列位置推断列边界。
- 误判风险高，**自动模式永不触发**，只有用户在编辑器里显式点「转成表格」才跑。

**D. 已是 HTML `<table>`（自动 + 手动：跳过）**
- 检测到既存 `<table>…</table>` 段落一律不动（保证幂等、保护编辑器已存内容）。

**通用**：不跨页；不含合并；幂等。

## 已决定的做法（本设计作出，非用户逐条确认）

- **新模块 `tableconvertmanage.py`**（对齐 `*manage.py` 命名；与管标签页的
  `tabmanage.py` 区分）承载纯函数：
  - `convert_text_tables(text: str, *, allow_space_aligned: bool = False) -> str`
  - 内部：`_iter_blocks`（扫描页面文本，切出表格块与普通行）、
    `_md_table_to_html`、`_box_table_to_html`、`_space_table_to_html`、`_cells_to_html`。
  - 供测试直接调用；不依赖 config/session。
- **自动接线 1（默认管线）**：`stringmanage.clean_and_structure_text` 增加参数
  `convert_tables: bool | None = None`（None = 懒读 `ui_settings.table_convert`，
  读失败回退 True）；开关开启时，在 `normalize_brackets(t)` 之后、`detect_headings(t)`
  之前对整页文本调用 `convert_text_tables(t)`（`allow_space_aligned=False`）。
  位置理由：必须在 `detect_headings` 前（否则表行被包成 `<h1>/<p>`），而表格转成
  单行 `<table>` 后，`detect_headings` 的「含 `<` 的行原样保留」规则会自然放行。
- **自动接线 2（矫正编辑器）**：`correctmanage._page_text` 的**原始文本分支**
  （`initial_html`）里，先 `convert_text_tables`（开关开启时）再按行包 `<div>`；
  **已含块标签的 HTML 分支不动**（保护历史/已存内容，天然幂等）。
- **手动入口**：新增无状态端点 `POST /api/table_convert`，请求 `{text}`，返回
  `{ok, html}`（内部走 `allow_space_aligned=True, require_separator=False`：手动档不强制
  分隔行）。前端 `ui/app.js` 弹出菜单新增
  op `table`（「转成表格」）：取选区文本 → 调端点 → 用返回 `<table>` 替换选区。
  op 纳入 `popup_row1/row2` 可配置体系（`POPUP_ELIGIBLE_OPS` 等），默认放进规则行
  之外的可选池，不强行占用现有默认位。
- **配置**：`config.json` 顶层键 `table_convert`（bool，默认 `True`），**主设置页**
  （`guimanage.py`）暴露复选框，实现方式完全仿照既有 `paddle_merge_lines`
  （渲染/收集/`/api/config` 白名单/CLI `mian.py config set table_convert false`）。
  只此一处存储，避免两份配置漂移；编辑器设置面板不加同义开关。
- **对齐 class**：单元格 ✕/✓ 对齐只用既有 class 名，不新造 CSS。
- **编辑器载入侧识别既存表格**（评审发现）：`_page_text` 现在按
  `</?(?:p|div|h[1-6]|span)>` 判定「HTML vs 原始文本」，**不含 table 系标签**，
  于是「只含 `<table>…</table>`、无 p/div/h/span」的页面会被当原始文本送进
  `initial_html` 转义成可见的 `<table>` 字样。修法（本设计采用）：把 table 系标签
  （`table/thead/tbody/tfoot/tr/th/td`）补进 `_page_text` 的探测正则（与
  `htmlmanage._BLOCK_TAG_RE` 同集合口径），并让 `initial_html` 对「整行就是一个
  完整 `<table>…</table>`」的行原样放行（不转义）作防御——两处都保证既存表格被当
  HTML 处理且幂等。
- **手动模式放宽分隔行要求**：手动 = permissive 档——有 `|---|` 用其定列/对齐；
  无则首行视为表头、其余为数据行；仍要求每行含竖线（否则不是管道表）。
- **表题产出显式 `<p>`**：避免其后的 `detect_headings` 把短表题升成 `<h1>`
  （会变成 EPUB 章节/TOC 条目，并在编辑器里被 `_headings_to_body` 归一）。

## 范围决定（已与用户确认）

1. **重新识别（re-OCR）不入 v1 范围**：`/api/reocr` 返回 `{text, diff}`、前端按字符级
   diff 应用，字符 diff 无法表达「N 行 → 一个原子 `<table>` 块」；改造它更侵入，先记录为
   **已知限制**，后续可单独做。
2. **空格/制表符对齐列（规格 C）只做手打文本**：矫正编辑器收到的文字已被 `normalize_spaces`
   折叠过空白，真实 OCR 的空格列在选中时已不存在；v1 只对「用户在编辑器里手打的多个空格」
   有效，真实 OCR 空格表记为**已知限制**。**不改动 `clean_and_structure_text` 的空白归一语义。**

## 交给实现者

- 各输入形态的**精确识别正则**与**边界条件**（如：几行才算表格、分隔行两侧允许的
  空白、全角变体的取舍），以测试锁定为准。
- 「表题提取」后与普通正文、与表格块相邻时的**输出顺序与空行**处理细节。
- 手动模式下**选区跨多个块**时的替换机制（复用编辑器既有表格插入/替换代码）。
- 编辑器设置面板复选框的最终落位与文案。
- `/api/table_convert` 与既有 `/api/convert`、`/api/clean` 的代码风格一致性。
