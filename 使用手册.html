概述

PToEA（仓库名 ptoe）是一个面向 Windows 的离线 PDF → OCR → EPUB 流水线工具：

  • 将 PDF 拆成图片
  • 对图片进行 OCR（本地推理服务：llama.cpp 的 llama-server 或 vLLM-Omni）
  • 清理、结构化识别文本
  • 可选人工矫正（浏览器/pywebview 内嵌 UI）
  • 生成标准 EPUB3（OEBPS/Text/Images/nav.xhtml + mimetype FIRST）

主要源码文件（快速索引）：

  • mian.py — CLI 入口、流水线编排、菜单
  • pdfmanage.py — PDF→图片拆分、ImageItem、ImageQueue
  • llamamanage.py / vllmmanage.py — 推理引擎适配（runserver / stopserver / batch_infer / request）
  • configmanage.py — config.json 读写（原子写 + 线程锁）
  • stringmanage.py — 文本清理与结构化（标题检测、页码剥离、bbox 转换）
  • correctmanage.py — 手动校对 UI 服务端及 apply_markers
  • guimanage.py — 配置中心 / 前端服务
  • htmlmanage.py / epubmanage.py — XHTML / EPUB 生成与打包

功能亮点

  • 本地推理（支持 llama-server / vLLM-Omni；可临时使用本地 PaddleOCR 作为 OCR 引擎）
  • 可选人工校对界面：按页对照原图并可标注标题/粗体/斜体/注释/段落/全文分篇
  • 中途断点续传（.ocr_progress.json）与历史版本缓存（data/correction_history/）
  • Windows 打包支持（PyInstaller onedir，默认生成 dist\ptoe\ 目录；可选 -OneFile 单文件）
  • 配置原子写入（tempfile + os.replace 与全局锁）避免损坏

前置要求

  • Windows（首选），Python ≥ 3.11
  • uv（项目使用 uv 管理依赖 / 运行脚本；也可直接用 python）
  • 可选推理后端：
  • llama.cpp + llama-server.exe（本项目默认/推荐，用于深度校对）
  • vLLM-Omni（vllm serve，适合 GPU 环境）
  • PaddleOCR（本地，仅作 OCR 阶段可用）
  • Python 包（常用）：pymupdf（fitz）、requests、zhconv。项目采用懒加载（失败时会降级或抛清晰错误）。

安装与依赖

在仓库根目录运行：

powershell cd D:\code-project\python\PToEA uv sync

说明：uv sync 会安装 pyproject.toml 中的依赖。若不使用 uv，可用 pip 在虚拟环境中安装：pymupdf, requests, zhconv 等。

配置（config.json）详解

配置文件位置：`./config.json`（项目工作目录下）。

程序首次运行会自动创建并用 DEFAULT_CONFIG 回填缺失键；若 `llama_server` 或 `models_dir` 指向不存在路径，默认会弹出 tkinter 文件选择（可通过 headless 模式跳过）。

关键配置（简要）：

  • llama_server: llama-server.exe 的路径（必填以便自动拉起服务）
  • models_dir: 模型文件目录（含 .gguf / .mmproj）
  • model_choices: 模型注册表，形如 {"HY": {"name":"HunyuanOCR.BF16.gguf","mmproj":"...","workers":2}, ...}
  • selected_model: 默认选中的模型键
  • engine: 推理引擎（"llama"（默认） | "vllm"）
  • llama_server_args: 启动参数（host、port、temperature、parallel、max_tokens、ctx_size、flash_attn 等）
  • vllm_server / vllm_server_args: vLLM-Omni 相关
  • gui_display: "pywebview"（默认内嵌窗口）或 "browser"
  • tabs_position: "top" / "bottom"（多标签窗口位置）
  • window_maximized: pywebview 是否默认最大化（布尔）
  • image_preprocess: OpenCV 预处理开关与选项（enabled, gray, denoise, sharpen, binarize, workers）
  • format_rules: 矫正界面的格式规则（可在 GUI CRUD 或写入 config.json）
  • shortcuts: 矫正界面快捷键映射（op -> 键组合）

建议：首次配置请先确保 `llama_server` 与 `models_dir` 指向有效路径，避免启动时弹出文件对话框阻塞。

通过命令行修改配置（不直接编辑 JSON）：

powershell uv run python mian.py config set llama_server "E:\xox\Tools\llama-c\llama-server.exe" uv run python mian.py config set models_dir "E:\model" uv run python mian.py config set selected_model HY uv run python mian.py config set engine vllm

若需在脚本中访问/修改：

python from configmanage import get_config, set_ocr_prompt, set_llama_server_arg cfg = get_config(show_dialogs=False) set_ocr_prompt("自定义提示词") set_llama_server_arg("parallel", "4")

快速开始（一次命令跑通）

powershell uv run python mian.py epub "E:\Books\example.pdf" --title "Example Book"

例子输出（示例）： [1/4] Splitting PDF to images (dpi=200) ... [2/4] OCR via llama-server (model='HY', workers=auto) ... [3/4] Structuring text (12 page(s)) ... [4/4] Rendering XHTML and packing EPUB ... Done: D:\code-project\python\PToEA\data\Example Book\Example Book.epub

CLI 参考（常用命令与示例）

主命令：`mian.py`（可通过 `uv run python mian.py -h` 或打包后的 `ptoe.exe -h` 查看实时帮助）。

核心子命令：

  • epub — 将 PDF 转为 EPUB（默认流程：split -> OCR -> structure -> convert -> pack）
    • 常用选项： --dpi {0..4}（0=100,1=150,2=200,3=300,4=600; 默认 0） --model MODEL（model_choices 中的键） --engine {llama,vllm,paddle} --workers WORKERS（OCR 并发线程，默认读取 model_choices.<key>.workers 或 3） --timeout TIMEOUT（单次请求超时，秒，默认 600） --thinking（启用思维链模式：不在提示词后追加“按原文原格式输出”） --title / --author / --lang / --out-dir / --epub-path --correct（开启矫正界面） --correct-timeout（界面关闭后自动继续等待秒数） --resume / --restart（断点续传或强制重识别）

示例： uv run python mian.py epub "E:\MYBooks\xxx.pdf" --title "书名" --dpi 2 --workers 3

  • resume — 继续上次中断的 OCR（只识别未完成页面或直接转换）
  • correct — 直接打开手动矫正界面（不跑 OCR，页面优先加载本地历史缓存）
  • model — 模型管理（list / show / set / add / remove）

    • 示例： uv run python mian.py model list uv run python mian.py model add NEW --name model.gguf --mmproj mmproj.gguf [--force]

  • config — 快速设置配置项（仅支持 set 子命令及部份嵌套键）
    • 示例： uv run python mian.py config set llama_server "..."
  • gui — 启动配置中心（本地 HTTP + pywebview 或浏览器）
    • uv run python mian.py gui [--host HOST] [--port PORT] [--no-browser] [--idle-timeout N]
  • stop — 停止推理服务（llama-server / vLLM）： uv run python mian.py stop [--engine llama|vllm]

打包 exe：双击 dist\ptoe.exe 将显示终端菜单（无参数 + 交互终端时），支持直接用 ptoe.exe epub <pdf> ... 等命令。

矫正界面（GUI）与手动校对详解

矫正界面为可选阶段（`--correct` 或 `mian.py correct`）：

  • 左侧：页面预览图（点击切换原图/预览）
  • 右侧：可编辑的 OCR 文本（每行一个 div，按行/段落保留原结构）
  • 工具栏：格式（粗体/斜体/标题）、标记（全文分篇/段落合并/注释）、搜索/替换、校正（候选替换）、图片插入、导出 TXT/DOCX/EPUB
  • 虚拟列表：支持 1000+ 页（只渲染视口附近 DOM）
  • 撤回/前进：Ctrl+Z / Ctrl+Y，最多 10 步
  • 历史：data/correction_history/，每个 PDF 保留多版本，包含低分辨率预览图以支持跨机器共享
  • 自动继续：关闭界面后等待 `--correct-timeout` 秒自动继续后续流程（默认 600s）

功能亮点：批量应用格式规则、全文标记与段落重拼接、注释标记与段落对应、实时搜索/替换（支持正则）、导出含未保存修改的全部页。

格式规则（Format Rules）说明与示例

格式规则由若干规则项构成（可在 GUI CRUD 或通过 /api/format_rules 写入配置）：

  • 规则对象：{id, name, mode("first"|"all"), conditions: [...]}
  • condition：{type: contains|prefix|suffix|regex, pattern, scope: selection|paragraph|page, formats: [ops]}
  • 支持 ops（示例）：bold, italic, h1..h6, align_left/center/right, note, remove, none

示例 1 — 注释段落识别： { "id": "rule-anno-1", "name": "注释段落识别", "mode": "first", "conditions": [ {"type":"prefix","pattern":"注：","scope":"paragraph","formats":["note"]} ] }

示例 2 — 章节标题（正则）： { "id": "rule-chap-head", "name": "章节标题识别", "mode": "first", "conditions": [ {"type":"regex","pattern":"/^第\\d+章\\b/u","scope":"paragraph","formats":["h1","align_center"]} ] }

示例 3 — 多条件组合（mode=all）： { "id": "rule-toc-block", "name": "目录条目美化", "mode": "all", "conditions": [ {"type":"contains","pattern":"目录","scope":"paragraph","formats":["h3"]}, {"type":"regex","pattern":"/^[0-9]{1,2}\\s+.+/","scope":"paragraph","formats":["align_left"]} ] }

数据流与输出结构

主流水线： 1) pdfmanage.split_pdf_to_images(pdf, dpi, fmt) → data/<pdf_stem>/1.png, 2.png ... 2) llamamanage.batch_infer（或 vllmmanage / paddleocrmanage）→ per-page OCR 文本 3) stringmanage.clean_and_structure_text → structured pages（去除页码、bbox 转换、段落/标题初步识别） 4) correctmanage.correct_pages（可选）→ apply_markers 5) htmlmanage.HTMLConverter → OEBPS/Text/content_N.xhtml、Styles、Images 6) epubmanage.EPUBPacker → .epub（mimetype 首项，ZIP_STORED）

输出目录示例： data/<pdf_stem>/ ├── 1.png, 2.png, ... ├── .ocr_progress.json ├── OEBPS/ │ ├── Text/content_1.xhtml │ ├── Styles/style.css │ ├── Images/ │ └── nav.xhtml ├── mimetype ├── META-INF/container.xml ├── content.opf └── <title>.epub

模型管理

模型注册表位于 config.json 的 `model_choices`：每个键对应对象 {name, mmproj, workers}：

  • name：gguf 文件名或相对路径（相对 models_dir）
  • mmproj：多模态视觉投影文件（当模型支持 vision 时）
  • workers：推荐并发数（batch_infer 未指定 --workers 时使用）

CLI 操作举例： uv run python mian.py model list uv run python mian.py model show uv run python mian.py model set HY uv run python mian.py model add NEW --name file.gguf --mmproj file.mmproj --force uv run python mian.py model remove OLD

注意：configmanage.find_canonical_model_key(choices, key) 提供一致的大小写不敏感查找逻辑；若存在大小写冲突会被视为歧义并报错提示。

OCR 断点续传（Resume / Restart）

  • 进度文件位置：data/<pdf_stem>/.ocr_progress.json（由 mian.py 的 _ocr_progress_path 确定）
  • resume：继续识别未完成页面（默认询问），`--resume` / `--restart` 可跳过交互
  • restart：忽略已有进度，从头识别全部页面（会覆盖进度）

打包为独立 exe（Windows）

仓库提供打包脚本（root）：0pack.ps1。

powershell -ExecutionPolicy Bypass -File .\0pack.ps1   # 默认 onedir，约 2.5 GB（含 GPU PaddleOCR）
powershell -ExecutionPolicy Bypass -File .\0pack.ps1 -NoPaddle   # 不打包 PaddleOCR 引擎，约 250 MB
powershell -ExecutionPolicy Bypass -File .\0pack.ps1 -OneFile   # 单文件 exe（可选，默认不用）

要点：

  • 默认 PyInstaller onedir + console（生成 dist\ptoe\ptoe.exe 分发包，含 _internal\）；单文件需显式 -OneFile
  • 打包定义集中在 ptoe.spec（脚本只设置开关并调用它）：--collect-all 常用包（pymupdf、zhconv、pywebview 等）+ --add-data dicts/ui/pyproject.toml
  • 建议使用 --noupx 以降低杀软误报
  • 体积（2026-09 优化）：约 2.5 GB，比旧脚本产物（约 4.6 GB）小 45%；裁剪在复制前完成，逐项实测依据见 ptoe.spec 头部注释

双击 exe 会显示终端菜单（交互模式），支持直接命令行用法：`ptoe.exe epub <pdf> ...`。

API / 程序化调用

仓库同时支持以库方式调用，示例：

python from mian import pdf_to_epub res = pdf_to_epub("E:/MYBooks/xxx.pdf", dpi=100, model_key="HY", max_workers=3, title="书名") print(res["epub"]) # EPUB 路径

也可分步调用： from pdfmanage import split_pdf_to_images from llamamanage import batch_infer from stringmanage import clean_and_structure_text from htmlmanage import HTMLConverter

split -> batch_infer -> structure -> convert -> pack

测试与验证

建议的快速 smoke tests（开发/修改后运行）：

uv run python -m unittest test_pdfmanage test_mian test_correctmanage test_llamamanage test_stringmanage test_vllmmanage uv run python test_image_queue_request.py

部分测试为 pytest 风格（如 test_config_llama.py），需要额外安装 pytest（uv add --dev pytest）。

常见问题与排查建议

  • 启动卡住弹出文件对话框：说明 config.json 中 llama_server 或 models_dir 路径不存在。用 `mian.py config set` 指向有效路径，或在 headless 下运行 `get_config(show_dialogs=False)`。
  • Read timed out / 单页超时：增加 --timeout，或降低 --workers / 降低 DPI 档位（dpi=2 较常用）。
  • 端口占用 / 无法启动模型：使用 `mian.py stop` 停止遗留服务，或直接 `python -c "from llamamanage import stopserver; stopserver()"`。
  • 打包后运行报找不到字典/数据文件：pack 脚本需把 dicts/、ui/ 等通过 --collect-all / --add-data 一并打包；本仓库 0pack.ps1 已包含常见收集操作。
  • Frozen exe 丢失编码/缓冲的问题：mian.py 有对 stdout/stderr 非 tty 下强制 UTF-8+行缓冲的处理。

高级 / 开发者注意事项

  • 线程与锁：configmanage 使用 module-level `_CFG_LOCK` 保护写操作；不要在持锁期间弹出 tkinter 对话框（实现上已把弹窗移出锁外）。
  • 原子写：使用 configmanage._atomic_write_json(path, obj)（临时文件 + os.replace）以避免写盘半截文件。
  • 推理后端：llamamanage 维护 module-global `_server_process` 与 `_SESSION`（requests.Session），保证连接复用；修改时注意不要破坏全局状态契约。
  • EPUB 内部路径必须使用斜线 `/`（htmlmanage/epubmanage 假定这一约定）。
  • 嵌入的 UI 脚本（correctmanage.py 中的 _UI_HTML / 内联 script）非常长且敏感：任何修改后请抽出 js 并用 `node --check` 进行语法检查；仓库含检查脚本 `check_js.py` 与 `extract_js.py`。
